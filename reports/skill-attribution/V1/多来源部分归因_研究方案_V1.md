# 面向复合 Skill 包与自有工具的开放集细粒度部分来源归因

> V1 · 研究方案与文献核验稿 · 2026-10-30（Asia/Shanghai）
>
> 本文是待实施的研究设计，不是已完成实验的成果报告。Markdown 为完整正文；配套 HTML 按相同内容制作 16:9 分页演示。文献事实、作者解释、本文推论和研究假设分别标注。

## 01｜摘要与研究定位

**研究对象：**包含自然语言指令、脚本、自有工具实现、配置、示例与参考资源的复合 Skill 包。研究这些内容经过复制、改写、拆分和跨包组合之后的部分来源关联。

**核心问题：**当公共成分、同功能独立实现、真实多源混合与缺失来源同时存在时，能否在定位复用区域的同时，减少把共有或未知内容错误地唯一归给某一候选的情况？

**拟议方法：**结构化切片 → 多路候选检索 → 局部表达／实现／操作证据 → 公共成分解释 → 多候选联合推断 → 保留歧义与未知；LLM 仅辅助有依据的提取和疑难核查。

**贡献预设：**评测与可辨识性设计、可靠区域输出、联合机制的增量价值。三者均需实验支持；组合现有技术本身不构成已经确立的创新。

## 02｜证据标准与核查范围

本文使用四类证据状态：**F（原文相关章节已核查）**、**A（摘要／官方条目已核查）**、**P（本文提出的方案或推论）**、**U（待补证据）**。F 表示核对了相应表述，不意味着论文代码已复现或结论独立验证。

- A：BLADE 官方会议摘要、DeRed 出版方检索摘要、选择性分类论文摘要、RedAct 摘要。
- U：DeRed 全文访问返回 403；未开展系统性综述，不能宣称“首个”“唯一”或“最优”。

核查日期为 2026-10-30。在线论文入口、版本和定位见文末；用户旧 HTML 是线索与样式参考，不作为独立学术证据。本文未复用其中未经核实的性能比较。

## 03｜研究对象与可见输入

[Agent Skills 规格 S01](https://agentskills.io/specification)描述以 SKILL.md 为核心，并可带 scripts、references、assets 等目录的结构。本研究以这种文件可见的复合包为主，并纳入能取得实现的自有工具。

| 输入 | 允许使用的内容 | 边界 |
| --- | --- | --- |
| 目标 X | 文件、路径、版本、可见声明 | 不读取秘密制作日志 |
| 候选源库 D | 候选版本及具体文件 | 不假定包含真实来源 |
| 公共库 C | 有内容与版本依据的模板、库、示例 | 包名或许可证本身不等于匹配 |
| 辅助信息 | 公开规格、引用、调用、可核查历史 | 缺失不等于没有依赖或复用 |

外部 API 仅能观察到声明与调用时，只对这些可见内容做关联；不能据此归因服务内部实现。首轮采用被动静态证据，不要求预埋水印，也不把 SOG 当作实际执行轨迹。

## 04｜符号、来源与“部分”的含义

- **A、B：**候选技能或工具实现。独立对照 B 按相同公开任务规格制作，制作时不能接触 A 的私有设计。
- **C：**有明确内容及版本依据的已知公共组件或共同上游。
- **X：**目标，可组合 A、B、C 的局部内容以及新写内容。
- **rᵢ：**目标区域；**D：**检测器当前可见的候选版本集合。

“部分”有两层含义：只解释 X 中有依据的区域；证据不足时，只给候选集合或未知。

**内容同源支持、直接获取路径、最初作者是三个问题。** 即使 X 中某段确定匹配 C，也未必知道制作时从 C 官网、A 的副本还是其他镜像取得。V1 主任务输出内容关联；方向和获取路径另列证据，不强行恢复唯一历史。

## 05｜输出语义与不可辨识性

| 状态 | 允许的结论 | 不允许的推断 |
| --- | --- | --- |
| 单一来源支持 | 当前证据优先支持 A | 已证明作者身份或侵权 |
| 已知公共内容 | 区域匹配具体 C@版本 | X 必然直接下载自 C |
| 歧义候选 | A 或 B 均能解释 | 已同时复制 A 和 B |
| 未知／证据不足 | 当前证据不够 | 已证明独立创作 |
| 多来源混合 | 不同子区域分别支持不同来源 | 只因同一区域像两方就判混合 |

**不可辨识示例（P）：**若 A、B 只有同一份 C 被保留到 X，且没有可靠历史记录，那么从 A 复制与从 B 复制可能产生完全相同的可见输入。算法应保留歧义，而不是猜中评估日志中的真实路径。

具体报告同时记录目标位置、源端位置、公共标记、证据类型、候选竞争和缺口；来源支持分不称为复制概率，区域占比不称为法律贡献比例。

## 06｜研究问题与可证伪假设

| 研究问题 | 待验证假设（P） | 失败判据 |
| --- | --- | --- |
| RQ1 可辨识性 | 分离公共、歧义和未知可减少错误唯一归因 | 只通过大量拒判获得低错误率 |
| RQ2 区域定位 | 局部表示能恢复整组件匹配遗漏的混合 | 收益仅来自真值边界泄漏 |
| RQ3 联合推断 | 有区分力的关系能改善候选竞争 | 同输入的成对汇总已同样有效 |
| RQ4 开放集 | 来源删除后能保留合理未知 | 缺失来源被稳定吸附到近邻 |
| RQ5 辅助核查 | LLM 降低疑难误判且成本可接受 | 只增加流畅解释或引入幻觉 |

主指标预设为：**固定明确判断覆盖率下的错误唯一归因率**。补充检索召回、区域定位、公共内容识别、歧义集合和未知检出表现。目标值必须在试点后确定并冻结，不在 V1 编造性能承诺。

**核查状态 F。** R01、R02 依据用户上传 PDF；R03 依据线上 §3、§5.1 和论文条目。不同论文使用不同数据集和标签，不能用各自报告的 AUC/F1 排成统一优劣榜。

“目前只有 SkillTrace 做技能内容复用检测”的旧说法应撤回。研究空缺应通过统一任务和基线实验建立，而不是通过排除其他工作建立。

## 08｜SkillTrace：可继承的方法与限制

**F｜R01 §III-C–F、§IV-B/F/H、§V-C。** E 比较自然语言 token；I 比较实现和命令 token；实现不足时为不适用。O 比较静态提取的操作块、激活、过程及资源流。

SOG 在入库阶段由 LLM 辅助提取，之后缓存并确定性比较。O 的四项固定权重分别为 0.30、0.10、0.40、0.20；成对融合为各适用轨迹的 `max(sₖ/τₖ)`，τ 来自 N1 严格负例的第 95 百分位。

**限制：**过阈值表示进入复核；每轨迹 5% 校准不保证融合后的总体 5% 误报。N1 排除了 shared-template-only 情形；全局野生语料路由没有使用 O，以避免通用流程碰撞。

**P｜迁移方式：**保留证据指针，将匹配扩展到区域／局部子图；重新校准局部分数。它已有局部证据，不能称为“只有整包分数”。

依据：[R01 原文](https://arxiv.org/abs/2608.05204v2)。

## 09｜Decomp-FP：身份指纹与版本标识

**F｜R02 §2、§6.3、§7、§9。** prompt、code、tools 分别编码并投影为 320 bit，三组件为 120 字节。缺失组件不参与对应比较；需要记录编码器版本。bank 是五个 64 位机器字布局，精度来自总位数，而非分组本身增加信息。

原文的身份是**技能家族身份**。SkillBOM 同时包含模糊指纹和密码学内容哈希；已有 novelty 检测和人工复核路由，不能说它完全没有未知处理。

**P｜本研究采用双层标识：**内容哈希标识精确快照；组件指纹查找近邻及家族。局部指纹是进一步扩展，不能直接沿用整组件实验结论。指纹相似度也不等于作者身份、行为安全或真实复制概率。

依据：[R02 原文](https://arxiv.org/abs/2606.31272v1)。

## 10｜组件分类与依赖图谱：各自负责什么

**F｜分类学。** [R04 §III-A、§IV 表 I](https://arxiv.org/html/2607.01456v2)研究 SKILL.md 正文的语义组件，报告 13 个高层、44 个低层类别；分析主要以 H2 段落为单位。它不等于整个 Skill 包的文件分类，更不是来源分类器。

**F｜依赖图。** [R05 §II-B2、§III](https://arxiv.org/html/2607.01136v1)提出 ASSCs 和 SkillDepAnalyzer，恢复 skill／package／service 依赖。它明确区分依赖重建与克隆检测；弱证据可保留为注释。

**P｜组合方式：**分类学作为文档区域的语义标签；脚本、配置和资源另按物理类型解析。ASSCs 式依赖帮助寻找上游候选与核对使用关系，但只有内容匹配和版本证据才能支持区域归因。

“使用同一个包／服务”不能直接推出“复制了同一实现”。

## 12｜可靠输出与邻近任务

[R10 选择性分类](https://jmlr.org/papers/v11/el-yaniv10a.html)研究拒判与风险—覆盖率权衡。**A｜本文借鉴评价口径，不能把其无噪声条件下的理论保证直接移植到相关区域、多源标签和检索遗漏场景。**

[R11 RedAct](https://arxiv.org/abs/2606.10813v3)研究执行轨迹中的能力泄漏、保护及行为水印。**A｜它属于邻近问题；主动水印与真实执行轨迹的结果，不证明 SkillTrace 的被动静态 SOG 能恢复复制历史。**

**P｜候选贡献边界：**“组件拆分”“图结构”“多个来源”“未知按钮”和“LLM 复核”均已有思想来源。可能的贡献是：统一任务与可辨识性标注，以及在相同候选和证据下，公共内容处理与候选竞争是否确实改善可靠区域归因。

V1 不承诺统计覆盖保证；如未来引入共形方法，需重新检验交换性、标签空间、检索遗漏和多源区域定义。

## 13｜总体架构与模块职责

```text
候选库／目标包／公共资源
          ↓
版本冻结 → 解析切片 → 文档语义标签与关系提取
          ↓
精确与词法检索 ∪ 组件指纹检索 ∪ 局部语义检索
          ↓
候选局部 E／I／O 匹配，保存源端与目标端位置
          ↓
已知公共内容核对 + 候选共有证据标记
          ↓
多候选竞争与关系一致性推断
          ↓
单一支持／公共内容／歧义／未知 → 汇总多源混合
          ↕
疑难案例 LLM 辅助核查（输出须绑定证据）
```

**P｜实现原则：**先完成确定性局部匹配和保守输出，再验证联合图与 LLM 的增量价值。检索、评分、公共标记、关系、判定分别记录，避免无法追溯的端到端总分。

## 14｜数据表示：三种粒度、两类图

**P｜三级对象：**包版本 → 组件／文件 → 区域。版本记录文件清单、原始字节 SHA-256、采集日期和来源地址；规范化文本另存，不能覆盖原始内容。

区域包含 `region_id、file、start/end、physical_type、semantic_tags、parent_id`。Markdown 按标题与段落，代码按函数并可细分语句块，配置按字段组；切片规则在评估前冻结。

**包内图：**引用、调用、参数绑定、先后、分支和资源流。**跨包图：**声明依赖、解析到的依赖、历史来源声明与内容匹配边。不同边类型不可混用。

每条边保存证据位置、提取方式和不确定性；模型推断边不能伪装成实测事实。操作块可关联多个文件区域。缺失边表示未知，不必作为关系冲突。文档语义标签可多选，首轮不强制训练 44 类分类器。

## 15｜多路检索与局部匹配

**P｜三路候选取并集：**精确／规范化词法匹配；Decomp-FP 式组件近邻；区域 embedding 近邻。分类仅排序，不作为跨类复用的硬过滤。公共组件库参与检索。

组件指纹主要负责召回，避免其与 E/I 使用同一内容时被重复当成独立证据。短片段先用词法和上下文；局部 SimHash 在规模需要时再加入并验证。

局部 E/I 保存 token 或语句对齐；O 比较区域关联的操作子图和边界上下文。报告目标覆盖、源端覆盖、匹配长度及稀有性。短目标对应长源片段时，Jaccard 可能低，应比较局部对齐／包含度基线。

阈值按区域类型、长度和可用轨迹在开发集校准；稀疏分组回退到共享阈值。禁止直接采用论文整包阈值作为局部唯一来源判据。

## 16｜公共内容：已确认、共有与未知

**P｜明确分开三个层次：**

1. **已知公共 C：**具体区域与可定位的 C@版本匹配，并有可复核的内容证据。
2. **候选共有：**A、B 都包含近似内容，但未找到足够的 C 证据；只能降低其区分 A/B 的能力。
3. **通用／低信息：**格式模板、标准接口和惯用表达；可降权，不据此创造一个虚构 C。

出现频率只用于特异性估计；先对镜像、版本和家族去重，避免把同一家族大量副本当作公共性的证明。源库中只出现一次也不等于作者独有。

公共片段保留在报告中；其“解释内容”的作用与“区分 A/B”的作用分开。如果 C 上有 A 特有的修改，继续定位这部分差异。确认公共内容仍不等于确认实际获取路径。

## 17｜联合解释的最小形式

**P｜这是研究设计，不是现有论文算法或已验证模型。** 对区域 i 的候选来源 s 计算局部支持 Uᵢ(s)，包括适用轨迹、对齐覆盖和经过共有证据处理后的特异性。已核实公共区域可先单独输出。

```text
Score(z) = Σᵢ Uᵢ(zᵢ) + λ Σ(i,j) Vᵢⱼ(zᵢ,zⱼ)
zᵢ ∈ 候选来源集合 ∪ {UNKNOWN}
```

V 检查两处匹配是否保留有依据的引用／调用／资源关系。**奖励对应关系成立，不简单奖励邻接区域同源。** 跨源组合可以是正确结果；来源转换次数不是默认惩罚项。

共享 token、共享图边按唯一证据单元去重；证据不适用或边缺失不赋负分。只有充分观察到且确实矛盾的关系才可形成惩罚。UNKNOWN 的基准及 λ 在开发集选择，公开配置和搜索范围。

## 18｜推断与决策：避免强制唯一标签

**P｜可执行的第一版：**每区域保留有依据的 top-k 候选；每个连通小图用整数优化求最优解释。为检查区域 i 的候选 s，可固定 `zᵢ=s` 重求最优，得到该候选的约束最优分 Hᵢ(s)。较大图采用有界搜索并报告近似误差／超时。

- 最佳来源的局部支持足够，且相对竞争解释有开发集校准后的优势：单一支持。
- 多个来源的 Hᵢ(s) 接近且各有支持：歧义集合；必要时记录未知仍可能存在。
- 所有来源支持不足：UNKNOWN。
- 不同子区域有明确不同来源：父区域汇总为多源混合。

分数不是概率。图规模、边密度和候选数量会影响差距，须归一化并做敏感性分析。小样本先用规则／线性特征，避免高容量模型掩盖证据不足。

## 19｜LLM 核查与直接来源方向

**P｜LLM 输入：**目标与候选的具体片段、公共 C 的实际内容、版本记录、提取到的关系及反例。不得提供制作日志和隐藏真值。

**允许任务：**核对改写是否保留特殊规则；检查公共 C 是否解释共有区域；验证操作边是否有文件依据。输出包括支持位置、反证、缺口及可弃权的判断。不得凭模型记忆捏造上游 URL。

LLM 的理由是已有证据的解释，不能作为新的独立证据再次计分。缓存模型、提示、输入哈希和输出；用固定疑难集对比无 LLM、规则复核和 LLM 复核。

方向信息另列 `direction_status`：仅有对称相似时为未确定；时间、fork、引用声明可补充支持，但较早出现不保证最初原创，声明也可能失实。未经核对不输出“B 抄 A”。

## 20｜贯穿示例：如何给出多源结果

**P｜示意例，不是实测。** A 和 B 均使用公共字段模板 C；A 有一套特殊冲突处理 a，B 有另一套输出格式 b。X 包含 C、a 的改写、b 的改写以及新写区域 n。

| X 区域 | 可见证据 | 输出 |
| --- | --- | --- |
| 字段模板 | 与 C@v1 对齐 | 已知公共内容 C |
| 冲突处理 | A 的特殊分支及调用对应 | 单一来源支持 A |
| 输出格式 | B 的特异格式与示例一致 | 单一来源支持 B |
| 新写区域 n | 无可靠匹配 | 未知；不声称已证明新写 |
| 另一个仅共有片段 | 同时匹配 A/B，未取得 C | 歧义 {A,B} |

X 的父级可汇总为多来源混合，但上述公共、歧义与未知区域分别保留。若删除 A，系统应倾向未知或保守歧义，而非把 a 强行归给 B。

## 21｜基准构造与真值隔离

**P｜首轮任务族：**沿用既有规划的文献元数据整理；先冻结标题／DOI 规范化、分组与年份冲突提示规格。制作 A、独立 B 和具体公共 C，分别冻结版本，再构造共享 C 的变体，不能回写独立形成史。

制作日志保存拷贝区间、变换、工具和时间；只进入评估端。检测端只读发布文件、候选库和允许的公开证据。独立 B 可用隔离人员或隔离生成会话，记录未接触 A；同一生成模型仍可能引入风格相关性。

同时保存两类真值：**形成史真值**与**可见证据允许的答案集合**。后者由不看制作路径的复核者检查，允许歧义和不可判定；不能要求系统从相同观察恢复不可辨识的唯一路径。

所有对照采用相同自动切片。真值边界只能用于评估或标明为 oracle 的上界实验。

## 22｜实验矩阵与试点规模

| 场景 | 变换／条件 | 主要考察 |
| --- | --- | --- |
| 单源局部复用 | 改名、重排、改写、添加无关内容 | 检索与定位 |
| 跨组件混合 | 文档 A＋脚本 B | 多源汇总 |
| 同函数混合 | 函数内 A/B 片段拼接与重构 | 细粒度定位 |
| 公共上游 | A/B 均含 C，X 仅留 C | 错误唯一归因 |
| 公共＋特异修改 | C＋a | 公共和特异证据分离 |
| 同功能独立 | 公开规格相同，形成过程独立 | 功能相似误报 |
| 来源缺失 | 删除 A；另测删除 C | 开放集与共有解释 |

**P｜建议试点而非统计承诺：**先做 3 个来源组，每组覆盖上述 7 类；确认输出与流水线后扩大来源组和任务族。扩展规模按家族层面的置信区间需求确定。样本数量、失败样本和重复次数全部报告，不能以切片数量冒充独立样本量。

## 23｜公平基线与消融

| 方法 | 固定条件下的差异 |
| --- | --- |
| B0 | 整包／组件指纹近邻，作为粗粒度起点 |
| B1 | 相同区域、相同候选的成对 E/I/O＋最高支持汇总 |
| B2 | B1＋公共／共有证据处理＋相同未知和歧义决策 |
| B3 | 普通加权覆盖：累计未重复解释的局部证据，不使用关系项 |
| B4 | 关系用于各个来源—目标的独立匹配，再做相同汇总 |
| M | 相同特征与关系下，跨候选联合解释 |
| M＋LLM | 固定疑难案例上的辅助复核 |

**P｜关键约束：**B1–M 使用同样候选、切片、公开信息和计算预算；B4 防止把“多拿到了结构信息”误写成联合收益。另做 oracle 候选、oracle 切片、去公共模块、去关系、去 LLM 消融，分别定位收益来源。保留可用的 SkillReuse 直接对照，并注明适配差异。

## 24｜评价指标与统计单位

**P｜主要终点：**在同一明确判断覆盖率下，比较错误唯一归因率。明确判断包括唯一来源与已知公共内容；分别报告其错误率，另提供只针对唯一来源的风险曲线。覆盖分母是全部可评估目标单位，不排除未知区域。

```text
Coverage = 明确判断的目标单位数 / 全部可评估目标单位数
Risk = 明确判断中的错误单位数 / 明确判断单位数
```

对不可区分 A/B 的区域，强制唯一归因即使碰巧符合制作日志，也计入“不受证据支持的唯一断言”。这与普通真值标签错误分开列出。

补充：候选 Recall@k；来源集合 precision/recall；区域 token／字符覆盖与 IoU；公共识别误报漏报；未知检出；歧义集合命中率与平均大小；单包耗时、LLM 成本和人工复核量。跨模态先分层，再做宏平均；置信区间按来源家族重采样，不把同包区域当独立样本。

## 25｜数据划分、校准与稳健性

**P｜防止泄漏：**按原始来源家族分组划分开发／校准／测试集；同一来源的变体不可分散。单独测试未见任务族与未见公共模板；原始规格、来源家族和公共模板的跨集合重合全部登记。

所有阈值、k、边权和拒判规则只用开发／校准集选择。最终测试同时报告固定阈值结果和风险—覆盖率曲线；不能从测试标签选择“最好看的”工作点。

同一 X 配对比较完整源库、删除真实 A、删除公共 C 三种条件。记录检索遗漏与源库真正缺失，避免混淆。加入镜像重复、短区域、模板比例升高、图边噪声和提取器版本变化的压力测试。

模型生成负例只是一类控制，不替代自然独立实现。LLM 提取温度为零也不保证绝对可复现，必须缓存实际输出。

## 26｜复核记录的最小格式

**P｜示例字段；不是实测记录。**

```json
{
  "target": {"version_hash": "…", "file": "scripts/clean.py", "span": [20, 38]},
  "status": "ambiguous",
  "candidates": ["A@v1", "B@v2"],
  "unknown_possible": true,
  "public_match": null,
  "evidence": [{"type": "implementation", "source_span": "…", "score": 0.82}],
  "missing": ["公共上游内容未取得", "无方向证据"],
  "direction_status": "undetermined",
  "pipeline_version": "prototype-config-hash"
}
```

分数示例不具有概率含义。正式记录另带源文件哈希、检索排名、归一化与切片版本、模型／提示版本、判定阈值和复核日志。采用候选集合时，保留未知可能性，不能以“集合非空”排除库外来源。

| 旧表述 | V1 修正及依据 |

## 29｜旧材料修正清单：判断与实验

- **不能由 A/B 整体不像推出 X 同时复制两者；不能由“像硬塞”判方向；不能由无独有签名推出公共 C。** 这些是缺少充分前提的推断，应改为局部证据审查和歧义输出（P）。
- **Decomp-FP 不是完全没有未知处理。** §6.3、§7.4 已有 novelty／review；但不是本方案的区域级开放集输出（F，[R02](https://arxiv.org/abs/2606.31272v1)）。
- **OOD 总体 AUC 0.739 不单独证明融合失败。** §5.3 仅 13 个正例对且标签较弱；标签问题是作者解释，V1 不将其写成独立证实的原因（F）。
- **跨语言恢复不能泛化。** 受控翻译中未变的 prompt 可承载匹配，不能据此宣称 code 普遍跨语言鲁棒（F，R02 附录 E）。
- **默认颜色、通用错误处理和普通 API 名不能自动成为独有签名。** 必须与规格、模板和背景语料比较；未知不等于独立（P）。

## 30｜限制、风险与 V1 结论

**主要限制：**候选库不完整；时间记录与来源声明可能失真；公共资源未收录；短区域信息不足；LLM 提取有误；片段边界与真实贡献不一致；同一证据重复计分；图结构可由功能需求自然产生。

**对策：**冻结版本、保存原始证据；显式标记缺失和不适用；对共有证据降区分权重；保留歧义与未知；以同信息强基线验证联合收益；报告错误案例和成本。

**V1 结论：**“语义分类＋组件指纹＋三轨迹＋依赖关系＋LLM 复核”可以构成工程框架，但每个模块各司其职。真正待验证的是：局部公共内容解释与多候选竞争，能否在相同覆盖率下减少错误唯一归因。

当前已完成文献相关章节核对与方案设计；本文未提供检测系统实现、实验数据或性能结果。下一步应冻结任务、制作独立对照并实现 B1/B2，而不是先扩展未经验证的复杂模型。
