# 复合 Skill 包与自有工具的多来源部分归因：研究对象、目标、现有工作与后续规划

- 研究负责人：陈杨烽
- 整理日期：2026 年 10 月 27 日
- 文档性质：研究定位与推进规划，供讨论和实施参考
- 整理依据：上传的《陈杨烽_多来源部分归因论文探索路线_2026-09-30.md》（正文注明 2026 年 10 月 6 日补充）及本次文献检索。
- 状态说明：本文区分已有文献结论、原路线所述进展和待验证方案；不将设想、手工例子或拟定实验写成实测成果。原附件引用的公开规格、样本说明等未随本次文件提供，实施时仍需取得并核对。

## 一、研究对象

### 1.1 研究什么

本研究面向可授权使用、修改和分发的复合 Skill 包，以及具有独立实现的自有工具。一个 Skill 包可能同时包含：

- 自然语言指令、处理规则与使用说明；
- 示例、参考材料与预期输出；
- 工具声明、参数字段与接口配置；
- Python 等语言编写的脚本及适配代码；
- 规则、示例、工具与实现之间可从文件中观察到的引用和调用关系。

研究场景是：这些内容被复制、改名、改写、拆分、合并或跨包组合后，如何依据可见证据判断新版本中各区域与哪些候选来源有关。

首轮场景拟采用“文献元数据整理”：清理合成记录中的标题和 DOI 写法，按公开规则分组，并提示同组年份冲突。具体任务语义以冻结后的公开规格为准。

### 1.2 基本符号与对照

| 符号 | 含义 | 作用 |
| --- | --- | --- |
| A | 一个原始 Skill 包或工具实现 | 提供候选来源和自有内容 |
| B | 未接触 A 私有设计、按相同公开要求制作的独立实现 | 检查同功能自然相似是否被误认为继承 |
| C | 有明确内容依据和版本的公共模板或共同上游 | 检查共有证据是否被错误归给单一候选源 |
| X | 待检测的新版本 | 可以混合 A、B、C 的部分内容及新写内容 |
| 源库 | 检测器可访问的候选版本集合 | 可以完整，也可以故意移除某个真实来源 |

A、B 独立版本先冻结；若需要共享 C 的变体，另建版本并记录形成过程，不回写原始独立形成史。共享生成模型本身不等同于可登记的公共组件 C。

### 1.3 研究边界

首轮采用被动证据，不要求源端预先嵌入水印。检测器只读取候选源库、目标文件、公开任务规格及各基线均可获得的依赖信息。制作日志、真实来源标签和模型会话等只用于评估端核对形成史。

本研究输出有证据支持的关联与不确定性，不直接判断侵权、许可合规或真实作者身份。功能相同不等于内容同源；当前源库中只出现一次的内容也不必然是作者独有。

若两条形成路径产生相同的可见输入，检测器不能凭内容恢复唯一历史。例如 X 只保留 A、B 共有的 C，即使制作时确实从 A 复制，也可能只能报告共有证据或无法区分的候选。

## 二、研究目标

### 2.1 核心问题

在候选源库不完整、公共成分与真实混合并存时，能否对拆改后的复合 Skill 包及自有工具进行细粒度的部分来源解释，在保留有效判断的同时降低错误直接归因？

“部分”有两层含义：允许只解释目标的一部分内容，也允许证据不足时只给出候选集合或未知。

### 2.2 期望输出

| 状态 | 含义 | 示例 |
| --- | --- | --- |
| 单一来源支持 | 当前可见证据足以优先支持某个候选源 | X 的某段实现与 A 的特异内容及对应关系一致 |
| 已知公共内容 | 匹配到有明确内容依据的公共 C | 公开模板、共同依赖片段 |
| 歧义候选 | 存在关联证据，但无法区分候选 | 同一区域与 A、B 的相同内容匹配，输出“可能为 A 或 B” |
| 未知或证据不足 | 现有源库和证据不能支持可靠判断 | 真实来源缺失或改写消除了可辨线索 |
| 多来源混合 | 不同子区域分别有证据支持不同来源 | 函数前半关联 A，后半关联 B |

“可能为 A 或 B”与“不同区域分别来自 A 和 B”必须分开表达。未知不等于证明独立创作；多个候选共享片段，也不等于已经证明存在某个未观测到的共同上游。

每条判断应保留目标位置、源端位置、证据类型、共有证据标记及必要的不确定性说明。匹配分不解释为复制概率，区域占比不解释为法律贡献比例。

### 2.3 研究问题

- **RQ1：可辨识性。** 哪些复用、独立实现和共同上游情形能由可见输入区分，哪些只能报告歧义？
- **RQ2：区域判断。** 自动切片与局部匹配能否定位同脚本、同函数内的来源混合？
- **RQ3：联合机制。** 在相同输入、候选匹配与结构信息下，联合解释能否优于合理成对汇总和普通加权覆盖？
- **RQ4：开放集可靠性。** 来源缺失或公共内容比例上升时，能否减少错误唯一归因，同时避免过度拒判？

## 三、现有工作与研究空间

### 3.1 当前判断

截至本轮检索，尚未发现一篇经本轮核查的论文完整覆盖“复合 Skill 包、同组件内部多来源混合、共同上游、缺失来源、带歧义的区域解释”这一组合任务。这是有限检索下的判断，不是对原创性的证明。

多个组成部分已有明确前身。因此，“输出多个来源”“增加图关系”“给出解释”“加入未知按钮”均不宜单独宣称为创新。

### 3.2 直接相关工作

| 工作 | 已完成的相关内容 | 对本研究的启示与边界 |
| --- | --- | --- |
| [SkillTrace，2026][1] | 表达、实现与操作结构三类证据；同功能独立负例校准；部分复用审计与证据指针 | 最直接的强对照。正式任务仍是成对审计，需检验其切片适配和合理汇总后是否已足够 |
| [SkillReuse，2026][2] | 对 YAML、自然语言和代码进行多模态克隆检测，输出克隆分数和类型 | 可借鉴候选检索、表示与变换设置；克隆相似不能直接当成真实派生关系 |
| [The Decomposition Is the Fingerprint，2026][3] | 分别为 prompt、code、tools 建指纹，识别家族关系及保留复用的组件 | 组件拆分与组件定位已有前身；需进一步研究组件内部区域及歧义 |
| [CENTRIS，ICSE 2021][4] | 通过代码分割及独有部分识别处理修改、嵌套的软件复用 | 公共成分处理与独有证据不是新概念，可借鉴其误报控制思路 |
| [LibAM，2023][5] | 利用函数调用图进行区域匹配，输出第三方库及对应复用函数 | 区域定位和结构支持已有先例；对象为二进制、粒度主要为函数区域 |
| [DeRed，2026][6] | 处理共享第三方库导致的虚假直接复用判断 | 与共同上游误归因高度相关；应优先补读，不能仅把它当普通克隆检测 |
| [LibXSub，2026][7] | 基于函数调用图与可解释子图检测二进制库复用区域 | 进一步说明“图＋区域＋解释”不足以单独构成创新，需继续全文核查 |

SkillTrace 已读取脚本与实现内容，并使用静态提取的操作图；不能描述为“只比较文本”，也不能把其操作图称为实际运行轨迹。SkillReuse 的 v2 已列出 ASE 2026 会议信息及 DOI，不宜把全部 2026 年工作统一称为仅有预印本。

### 3.3 可以重点借鉴的方法

**共同上游误归因：DeRed 与 CENTRIS。**  
DeRed 的出版方摘要描述了利用函数调用图中心性及与导出接口的连通性，区分供体与接收方区域。本研究可以借鉴其误归因场景和对照设计，但二进制结构规律是否能迁移到 Skill，必须另行验证。

**局部到区域：LibAM。**  
借鉴从局部匹配产生锚点，再形成结构区域并检查对应关系的流程。来源检出与区域定位应分别评价，不把“找到某个库”视为已经正确识别其全部贡献。

**拒判评价：选择性分类。**  
借鉴风险—覆盖率曲线：在相同明确判断覆盖率下比较错误率，或在相同错误率要求下比较能保留多少有效判断。[8]

**未知与候选集合：开放集预测。**  
开放集共形预测提供了未见类别及集合输出的参考。[9] 其统计保证不能直接移植到本任务：同包片段存在相关性，检索可能遗漏候选，区域也可能真实多源。首轮先验证输出语义与经验指标，不预先承诺理论保证。

### 3.4 可能的贡献与尚未证实的部分

| 层次 | 候选贡献 | 成立条件 |
| --- | --- | --- |
| 任务与评测 | 联合覆盖真实混合、共同上游、独立同功能和来源缺失的评测 | 形成过程可信、真值与检测输入隔离，且不止少量手工例子 |
| 可靠输出 | 区分唯一支持、公共内容、歧义候选和未知的区域解释 | 明确语义，在固定覆盖率等公平条件下降低误归因 |
| 方法 | 对重叠证据、候选竞争及特异关系进行联合解释 | 在相同输入和关系下优于强成对方法与普通覆盖基线 |

变量绑定一致性本身可以通过分别检查 A—X、B—X 实现。它能够说明结构对应有价值，尚不能证明必须跨来源联合推断。若收益来自更多脚本、更细切片或更好的关系提取，应分别报告，不能全部归为联合算法收益。

### 3.5 文献核查范围

本轮查看了 SkillTrace、SkillReuse、组件指纹和 LibAM 的公开全文相关段落，以及 CENTRIS、开放集预测的论文摘要或记录。DeRed 全文访问返回 403，目前主要依据出版方检索摘要；LibXSub 全文页面访问受限，目前依据出版方索引内容和官方仓库说明。

上述比较不代表所有论文已逐页精读或代码已复现。特别是 DeRed、LibXSub 的输出粒度、失败条件和复现成本仍需补充核查。

## 四、已有进展与当前缺口

根据上传路线所记录的状态，已完成研究问题梳理，明确了统一自动切片、强成对基线、共有证据处理、真值隔离及来源缺失对照等原则。本次又补充了近邻文献与创新边界分析。

原路线注明当时尚无 A、B、混合样本、自动切片或运行结果。本轮未取得新的实现成果，因此本文仍将这些项目列为待完成，不推断当前已经实现或验证。

主要缺口包括：

1. 冻结的功能规格与独立实现 B；
2. A 的交接及可核查的样本形成记录；
3. 自动切片、实际区间匹配与强基线；
4. 证明普通成对汇总或覆盖仍不足的实际案例；
5. 明确的联合评分、关系作用范围及歧义保留规则；
6. 独立开发集与测试集上的实测结果。

## 五、后续规划

采用按交付物推进的阶段安排，不预设未经确认的日历截止时间。

### 阶段一：固定问题与制作独立实现

- 取得公开规格和样本形成说明，冻结功能要求、可见输入及输出语义。
- 在不接触 A 私有设计的条件下制作 B，完成对应功能检查并记录版本。
- 确认工具实现实质参与归因，而非只比较 SKILL.md。
- 建立真值记录格式，分开保存制作路径与检测器输入。
- 补读 DeRed、LibAM；核查 SkillTrace 的实现来源和可复现范围。

**交付物：** B、功能检查结果、输入输出约定、文献边界核对表。B 的实现和切片起点不必等待 A。

### 阶段二：自动切片与强基线

- 规则按完整条目，示例按完整案例，代码按函数及必要适配片段切分。
- 加入预先固定的 token 窗口或语法块，覆盖函数内部混合。
- 切片程序不得读取真值边界；保存实际匹配区间。
- 建立原始 token 与标识符规范化 token 两路匹配。
- 公共规格、公共依赖和高频共有片段降权或单独标记。
- 使用开发数据固定阈值、候选差距及未知规则。

**交付物：** 切片程序、匹配起点、区间证据表和可复核的区域输出。

### 阶段三：混合样本与对照

A、B 冻结并完成交接后，制作形成过程明确且通过功能检查的样本：

| 场景 | 核心检查 |
| --- | --- |
| 同文件、同脚本混合 | 是否能保留多个真实来源 |
| 同函数内部混合 | 自动粒度是否掩盖来源边界 |
| 仅保留共有 C | 是否误给 A 或 B 唯一来源标签 |
| 同功能独立 B | 是否把功能相似误认为继承 |
| 移除真实来源 | 是否转而错误指向相近的库内候选 |
| 改名、拆分、合并及改写 | 哪类证据仍然有效 |
| 工具抽取后独立分发 | 是否能识别实现层面的局部关联 |

不因独立 B 被检测命中就重新生成低相似 B。开发与测试尽可能按源家族隔离，同一原版的近似变体不能跨集合泄漏。首轮小样本用于找机制和问题，不估计整个生态的误报率。

**交付物：** 版本化样本、功能检查、形成日志、隔离的评估真值及预先规定的允许输出。

### 阶段四：比较基线与联合解释

| 编号 | 方法 | 检验目的 |
| --- | --- | --- |
| B0 | 局部匹配＋公共过滤＋拒判 | 建立合理起点 |
| B1 | 成对匹配结果合并＋实际区间去重 | 检查简单汇总是否足够 |
| B2 | 普通加权覆盖＋相同未知选项 | 检查重叠匹配能否由简单全局办法解决 |
| B3 | 成对结构匹配＋相同切片和汇总 | 排除收益仅来自结构信息 |
| M | 候选联合解释 | 检验跨来源决策是否有独立增量 |

各方法读取相同文件和候选源库。关系特征也提供给结构强基线。对 SkillTrace 等方法进行切片适配时，明确哪些是原方法、哪些是近似重建或新增适配。

M 首版可采用有限候选枚举或简单打分，保留同等支持的多份解释。不得重复计算同一区间的公共支持，不以最少来源数压掉真实混合，也不因 A 的规则调用 B 的工具就强迫二者同源。

**交付物：** 完整对照结果、消融分析、至少若干来自实际文件的成功与失败案例。

### 阶段五：可靠性评价与方向判断

建议固定评价单位，并分别报告：

- 错误唯一归因：明确指向单一来源的错误情况，同时报告明确判断数量；
- 有效来源召回：有可区分证据的来源被保留多少；
- 区域质量：按预定义 token 或区间评价定位准确性，避免重叠窗口重复计数；
- 公共内容误指认率：公共区域被指成单一候选特异内容的比例；
- 缺失来源误指认率：真实来源被移除后，内容被错误归给库内候选的比例；
- 风险—覆盖率：相同明确判断覆盖率下比较错误率；
- 歧义集合质量：允许答案是否保留，以及候选集合是否过大；
- 提取与计算成本：若使用大模型提取关系，单列调用成本、版本和波动。

在小样本阶段同时给出原始计数和案例；扩展阶段再按来源家族进行不确定性分析。

**方向判断：**

- 若联合机制在公平比较下稳定改善结果，扩大任务、来源家族与自然改写范围。
- 若 B1/B2/B3 已足够，不继续用复杂模型包装同样结果；可以转向评测、可辨识性和可靠输出。
- 若未知误归因严重，先修校准与开放集判断。
- 若主要困难在观察上不可辨识，明确保留歧义，不能要求算法猜中制作历史。

## 六、近期优先级

1. 固定研究对象、检测器输入和五类输出语义。
2. 补读 DeRed、LibAM，并精确核对与 SkillTrace 的任务差异。
3. 按公开规格制作 B，完成自动切片和局部匹配起点。
4. A 交接后制作同函数混合、共有内容及来源缺失的最小对照组。
5. 用 B0—B3 与 M 的公平比较决定是否保留联合方法。

当前宜使用的题目是：**面向复合 Skill 包与自有工具的开放集细粒度部分来源归因**。最终题目与贡献表述应随实测结果调整。
